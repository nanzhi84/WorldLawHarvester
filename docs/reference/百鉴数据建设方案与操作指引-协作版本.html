阅读说明：一套体系、三份载体

百鉴数据建设采用“一套体系、三份载体”：

  • 本方案统一数据建设的方向、对象、模式、核心机制和治理责任；
  • 《项目数据建设操作指引》用于项目培训和执行，说明各角色如何协作、各环节如何开展；
  • 《项目数据建设工具包》用于统一来源评估、标签定义。

本方案不展开逐文件处理方法和表单字段，具体操作以配套指引和工具包为准。

一、建设定位与目标

1.1 建设定位与目标

百鉴的数据建设以行业标杆客户的真实项目为起点，持续建设能够服务当前项目、又能被后续项目复用的法财税数据资产和专业知识资产，形成项目与数据建设相互促进的长期机制。

1.2 建设原则

  • 项目牵引：优先建设真实客户场景需要的数据，项目需求决定建设优先级。
  • 专业主导：来源权威性、标签语义和专业适用性由专业人士判断。
  • 统一沉淀：公域数据维护统一主记录，避免不同项目重复维护同一资料。
  • 系统治理：用标准、规则和系统质量控制支撑规模化建设，不以逐文件人工审批作为常态。
  • 持续迭代：项目应用效果和外部数据变化共同驱动数据、标签、规则与知识更新。

二、建设对象与资产体系

2.1 建设对象

百鉴建设的是两类可治理、可服务的资产：

资产类型主要内容建设重点沉淀位置
公域数据资产法律、法规、政策、案例及其他公开法财税资料来源、原文、元数据、标准化文本、标签、版本、效力状态和更新状态法财税公域总库
机构知识资产经授权、脱敏且可跨项目复用的方法、Checklist、评测集、研究路径和专业经验适用范围、专业验证、知识结构和复用方式百鉴机构知识库

公域数据回答“有哪些有效依据”，机构知识回答“如何运用这些依据解决问题”。两类资产共同支撑客户项目、专业研究、知识库检索和智能体应用。

2.2 法财税公域总库：统一公共数据底座

法财税公域总库提供和接收各项目所需的公开专业数据，形成百鉴统一维护的公共数据主记录，主要包括：

  • 法律、法规、规章和规范性文件；
  • 监管政策、监管问答和办事指南；
  • 司法案例、行政执法和处罚案例；
  • 财务、会计、税务、海关资料；
  • 行业监管规则及公共行业资料；
  • 具有使用价值的专业研究和解释资料。

总库通过国家/地区与具体法域、行业、专业领域、业务场景、文档类型、发布机构、效力和时效状态、适用主体、来源等级及语言关系等字段和标签组织数据。同一份资料只维护一套主记录，但可以同时服务多个分类和项目。

2.3 百鉴机构知识库：沉淀可复用专业能力

百鉴机构知识库接收项目中形成的、经授权和脱敏、经过专业验证并具有跨项目复用价值的方法、Checklist、评测集、研究路径、专业解释、判断规则和实践经验。

机构知识库不是项目材料的简单汇总，而是把项目中已经证明有效的工作方法和专业经验转化为后续项目可以直接查找、调用和继续迭代的组织能力。

三、项目驱动的建设模式

3.1 数据建设飞轮

数据建设飞轮以“标杆客户项目”为起点：项目提出真实业务问题，推动数据与知识的定向建设；建设成果在项目中应用和验证后沉淀为公共资产，再支撑更多标杆客户项目进入下一轮建设。飞轮的关键不只是“项目结束后归档”，而是项目在建设前复用已有资产、建设中产生和验证新资产、使用后把有效结果持续沉淀。项目越多，公共资产越丰富；公共资产越成熟，新项目建设的速度和质量越高。

3.2 一个项目如何参与数据建设

阶段项目与数据资产的关系主要结果
项目启动从客户问题出发，明确行业、法域、业务场景和专业问题；优先检索已有资产确认可复用资产和新增建设需求
项目建设对缺口数据开展来源确认、采集加工、标签和质量验证；同步识别可复用专业知识形成可在项目中使用的数据与知识
项目应用在客户场景中使用数据、标签和专业知识，发现适用性、准确性和检索问题形成实践反馈和改进需求
持续沉淀新增公域数据进入统一主记录，可复用专业知识进入机构知识库扩大公共资产并服务后续项目

3.3 两条资产建设路径

路径起点关键判断最终结果
公域数据建设项目数据需求和专业人士提供的数据源来源是否权威、数据是否标准、标签是否有效、版本是否可维护法财税公域总库主记录与项目查询服务
机构知识建设项目形成的方法、工具和专业经验是否获得授权、完成脱敏和专业验证、能否跨项目复用百鉴机构知识库中的可复用知识

两条路径共同来源于项目，但分别解决“公共依据如何统一维护”和“实践能力如何持续积累”两个问题。

3.4 数据资产的核心保障机制

  • 来源权威与可追溯机制
  • 统一标准与结构化机制
  • 场景标签与专业规则机制
  • 知识关联与知识图谱机制
  • 质量准入与专业复核机制
  • 时效与版本管理机制

5.2 评价标准

本方案不以采集文件数量作为主要成功标准，而以以下结果判断数据建设是否有效：

  • 有用：数据和知识能够支持真实客户问题、专业研究、检索和问答；
  • 可信：来源权威，原文、版本、标签和处理过程可以追溯；
  • 有效：新增、修订、替代和失效能够被发现并反映到可用版本；
  • 一致：不同项目按照统一标准建设，同一公域数据不形成相互冲突的主记录；
  • 可复用：项目新增资产能够进入公共体系，并被后续项目直接调用；

5.3 贯穿案例：从法律问题倒推标签和知识关系

本例以越南制造业投资项目为场景，并使用越南《投资法》（第 143/2025/QH15 号）、第 96/2026/NĐ-CP 号法令和第 08/2024/KDTM-PT 号厂房租赁合同纠纷判决作为规则样本，演示三个动作如何形成对应结果。

1. 拆解专业问题，形成数据需求

专业人士先把客户提出的研究事项拆成可以由数据支持的专业问题，再确定需要哪些类型、哪些内容的数据。

项目需求需要回答的专业问题对应的数据需求
投资设立外国投资者设立制造项目需要履行哪些投资和登记程序投资程序、主管机构、申请材料、办理要求及相关案例
市场准入拟从事的制造活动是否存在外资准入限制及附加条件外资准入规则、受限制经营活动、持股或投资形式限制及实施文件
生产许可工厂建设和投入生产需要取得哪些许可、审批或备案与制造活动相关的生产经营、建设、环保、安全等许可规则及办理要求
税务优惠项目可以适用哪些税收优惠以及需要满足什么条件税种、优惠条件、优惠方式、适用期限、办理程序及主管机关解释

标签维度本例标签支持的使用场景

行业与经营活动制造业；具体制造活动将通用投资规则与具体经营活动要求结合查询

关系类型及方向本例关联对象建立依据支持的使用场景

一、工具包怎么使用

本工具包只记录需要跨角色确认的数据范围、专业规则和标准交付，不为每个步骤单独设置表格。任务状态、质量检查、专业抽检、批次验收和发布结论由系统留痕，避免重复填写。

系统可以在后台生成任务、来源、文件、批次和知识资产的唯一标识，并自动建立关联。项目成员使用项目名称、来源名称、资料名称和批次名称开展工作，不需要记忆或手工填写系统编号。

本工具包中的示例沿用同一项任务：某制造业标杆企业拟在越南投资设厂，项目需要建设投资设立、市场准入、生产许可和税务优惠相关数据，并为客户提供可检索、可问答的知识库。示例使用现行越南《投资法》（第 143/2025/QH15 号）、第 96/2026/NĐ-CP 号法令和相关案例演示表单填写方法。真实资料仅用于演示数据建设方法，项目使用时必须重新核验适用时点的正式文本、修订情况和有效状态。
